# StockFlash — Validaciones pendientes con disparador (2026-10-15)

**Regla:** una validación pendiente no equivale a PASS. Los controles que son puerta de entrada de una etapa deben ejecutarse antes de esa etapa; **no** posponer viabilidad esencial o privacidad hasta producción. El agente debe verificar la evidencia, anotar `PASS/FAIL/UNVERIFIED` y reportar bloqueos.

| ID | Hecho que falta demostrar | Impacto si falla | Validación / evidencia aceptable | Disparador | Estado |
|---|---|---|---|---|---|
| DV-001 | Delegación real `Build → stockflash-orchestrator → implementer → gates → reviewer → publisher` | Operación no autónoma, pasos manuales y falsa evidencia | Un packet-smoke aprobado, transcripción real de agentes, fingerprints, revisión atribuible, push y comparación de SHA; sin agentes simulados. Si falla, aislar configuración de permisos, `mode`, profundidad y versión instalada. | **Antes** de adoptar una cola `/queue-run` o AutoPilot; idealmente en una tarea administrativa previa a R3. | UNVERIFIED |
| DV-002 | Versión real OpenCode, sintaxis cargada de `opencode.json` y modelos accesibles | Config incompatible y prompts de permisos | `opencode --version`, `opencode models`, confirmación de comandos/agentes recargados y smoke básico. V1 `permission/task/agent` no equivale a V2 `permissions/subagent/agents`. | Antes de cualquier modificación administrativa de permisos/modelos. | UNVERIFIED |
| DV-003 | Aislamiento staging, `document root`, credencial limitada, respaldo y rollback | Deploy afecta producción, exposición de datos o recuperación imposible | Inventario de capacidades reales cPanel, credenciales por mecanismo fuera de Git, reversión probada y smoke en entorno separado. | **Antes de aprobar** cualquier packet de deploy de STAGING-001. | UNVERIFIED / BLOQUEANTE R2 |
| DV-004 | Versión MariaDB y viabilidad de migraciones desde el esquema contractual | Cambios estructurales incompatibles o reescritura del modelo | Versión verificable (>=10.6 según roadmap), migración reproducible en DB de pruebas aislada, FK ordenadas y rollback comprobado. | Antes de primera migración R3. | UNVERIFIED / BLOQUEANTE BD |
| DV-005 | Criterios de seguridad/privacidad para autenticación, roles y datos personales | Riesgos desde el diseño de RBAC y tratamiento de datos | Revisión de amenazas **proporcional**, autorización servidor, aislamiento, retención y controles básicos; hardening extra antes de exposición pública. | Antes de implementar autenticación / persistencia de datos personales de R3; revisión de despliegue adicional antes de release. | PENDING / BLOQUEANTE POR MÓDULO |
| DV-006 | Integración visual de SVG provisional, legibilidad a tamaños pequeños y fallback | Identidad inconsistente o inaccesible | Revisión humana/perceptual + criterios por pantalla; no basta validar XML y colores. | Antes de autorizar usar SVG como identidad primaria en una pantalla. | PENDING / NO BLOQUEA R2 |
| DV-007 | Diseño real de RUN-REPORT/ledger implementado por scripts y conectado al flujo OpenCode | Informes inventados o desfasados | Unit tests de parser/ledger, ejecución real, hash de archivos revisados, CI consultada por SHA, bloque explícito `UNKNOWN` si no verificable. | Antes de usar RUN-REPORT como prueba automática o aceptar `/queue-run`. | DOCUMENTADO / NO IMPLEMENTADO |

**Semántica:** `PENDING` = no solicitado; `UNVERIFIED` = investigado o supuesto sin prueba; `BLOQUEANTE` = impide el hito indicado, no todo el proyecto.
