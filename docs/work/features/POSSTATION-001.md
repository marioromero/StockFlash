2. Only users with existing `settings.manage` on the relevant active branch may manage it. Real server-side guards, not just hidden buttons.
3. POS module gating fail closed using current entitlement and installation module convention; do not make POS stations independently billable. License read-only blocks mutations but permits permitted reads. Ensure public /roadmap and /docs/, /setup one-time guard, CUSCORE privacy and SELLERS scope unchanged. Dashboard link only for authorized managers while enabled.
4. Device identity: provide **explicit authenticated administrator action** `bind this browser to station` to generate a cryptographically secure >=256-bit random token, store only its SHA-256 hex digest in `device_token_hash`, and set the raw token only as a `HttpOnly`, `SameSite=Strict` cookie (Secure in HTTPS; localhost dev HTTP handling consistent with existing application). No raw token in DB/HTML/Inertia props/JSON response/query URLs/logs/audit/redirects; do not display/copy it to an admin page. On rebind/revoke/deactivate/branch change invalidate the old token atomically. A read-only resolver must identify the station by cookie hash plus active station/branch for future authenticated POS flows; token identity NEVER authenticates a user or grants permissions. Do not auto-issue tokens on GET/login; no background heartbeat.
5. Access-scoped station listing/detail must never include `device_token_hash`, token or secret. Rotations and status mutations audited in same DB transaction as record changes (station ID, branch ID, changed field names, nonsecret flags only); if audit fails, rollback token changes, assignments and status. Device identification is read-only; `last_seen_at` remains null until an explicitly defined future POS event. Do not claim actual sales sessions are bound.
