### 1. Durable timeline CLI

New `scripts/sf_timeline.py` with local-only `begin`, `end`, `status`, `summary` actions and tested reusable Python API for safe `sf_verify` instrumentation:
- Feature IDs strict allowlist, e.g. uppercase `[A-Z0-9][A-Z0-9-]{2,63}`; stage/agent/status/trigger **closed enumerations**. Never accept arbitrary user payload or filesystem path as a timeline parameter. Store under `docs/work/.run/<ID>.timeline.jsonl` (already ignored). Event schema includes version, event type, timestamp UTC/epoch ms, stage, safe agent role, attempt/correction ordinal where available, outcome, span correlation and source (`observed_stage_boundary` or `native_gate_runner`). No raw prompts, tool arguments, shell commands, stdout/stderr, customer data, session ids, passwords, .env or Git credentials.
- `begin FEATURE STAGE --actor ROLE` persists a start before delegation and returns short span ref. `end FEATURE STAGE --actor ROLE --status PASS|FAIL|PARTIAL|BLOCK` closes *the unique matching open span*, or reports an explicit ambiguous/missing close error without fabricating elapsed time. Stage labels at minimum: `implementation,verification,qa,correction,publication,ci` (plus `preflight` if useful). Missing end remains ACTIVE/INCOMPLETE, never a fabricated PASS or zero duration. Handle serial repeated stages, restarts, malformed/corrupt/truncated last line and timestamp clock skew conservatively.
- `status FEATURE` shows active stage(s), started-at/duration-so-far (observed clock), most recent closed stages, and incomplete/unknown markers. `summary FEATURE` provides deterministic concise Spanish owner-facing summary (no free text): elapsed stage durations, actor, attempt count, PASS/FAIL/BLOCK/PARTIAL, number and total duration of `sf_verify` runs and per-gate safe identifiers/durations if integrated, active/open intervals and limitations. Overlap: do NOT add overlapping durations and label sum vs union explicitly. Wall-clock idle is UNKNOWN unless timestamp evidence supports it; no claiming model/queue latency. Status/summary must be read-only.
- Updating local checkpoint `docs/work/.run/<ID>.json` may add exactly one `telemetry` subtree with current stage, last event and update time; **preserve every existing checkpoint key** and avoid overwriting unparseable checkpoints, producing a warning instead. Existing orchestration checkpoint remains authoritative for gate/QA/publisher fingerprints; telemetry must NOT replace or loosen its evidence.
- Use atomic append/appropriate file locks across Windows and Linux where practicable; never leak file contents in errors. Fail closed on unsafe feature ID/traversal. On telemetry write failure, emit concise TELEMETRY_UNAVAILABLE and continue normal workflow/gates, recording coverage gap where possible; telemetry failure must NEVER turn a failed gate green or block approved work.
- Storage only local ignored directory; no sending metrics automatically to GitHub or external provider. No new secrets or untracked source writes. Tool stage updates should cost just one tiny CLI operation at a genuine stage boundary, not on each request/tool call.
