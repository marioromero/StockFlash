- `LoginController@store` (`LoginController.php:74-100`): regenera la sesión, registra `last_login_at`/IP y guarda `session_started_at` + `last_activity` después de regenerar, antes de redirigir.

- Cada sesión queda anclada a su propio `session_started_at`; un login nuevo no reescribe el inicio de otra sesión que ya tiene la clave.
- Pruebas reales vía kernel HTTP en `tests/Feature/Auth/SessionTest.php`:

### 3. `EnsureBranchAccess` — CONFORME (con observación no bloqueante)

- Usuario no autenticado → redirección a login; usuario global → permitido (`EnsureBranchAccess.php:27-34`).
- Identificador resoluble desde ruta (`branch`/`brand`), parámetro del middleware, request (`branch_id`) o `default_branch_id`; si no hay identificador (null/vacío) → `abort(403)`, sin bypass (`:38-46`).
- Resolución por ID numérico o por `code`; sucursal inexistente → 403 (`:49-55`).
- `Branch` usa `SoftDeletes`, por lo que una sucursal eliminada lógicamente no se resuelve → 403.
- El acceso sigue exigiendo fila en `branch_user` para la sucursal resuelta (`:59-63`); el fallback a `default_branch_id` no omite esa comprobación.
- Pruebas HTTP reales en `RbacTest.php:254-394`: sin sucursal/sin parámetro 403; inexistente por ID 403; inexistente por código 403; válida por ID 200; global accede a cualquier sucursal 200; soft-deleted 403; usuario de A no accede a B 403; usuario de A accede a A 200.
