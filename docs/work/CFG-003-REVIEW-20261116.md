## Criterios del packet

1. **GET/PUT `/settings/general` y middleware — CUMPLE.** Ambas rutas viven dentro del grupo `auth` + `password.change` + `verify.session`; el subgrupo aplica `can.permission:settings.manage` y no `branch.access`. El test de rutas lo comprueba. El enlace del Dashboard usa `v-if="canManageSettings"` derivado de `settings.manage`. PATCH no está registrado y el test devuelve 405.
2. **Siete claves, defaults y UI — CUMPLE.** Controller y request declaran exactamente `country`, `currency_code`, `currency_decimals`, `timezone`, `locale`, `prices_include_tax`, `cash_rounding_step`, con defaults `CL`, `CLP`, `0`, `America/Santiago`, `es-CL`, `true`, `1`. `prices_include_tax` se persiste como `1`/`0`. La pantalla muestra solo esos campos, agrupados y responsive.
3. **Allowlist estricta y no exposición — CUMPLE.** GET solo consulta las siete claves (`whereIn` + `pluck`), sin `responsible_*`, `fiscal_provider_config`, comprobante ni `is_setup_completed`. PUT solo inserta/actualiza las siete claves. Las validaciones son técnicas (ISO de país/moneda, entero 0–4, timezone identificador, formato idioma-región, booleano, entero mínimo 1), sin reglas comerciales nuevas.
4. **PUT completo — CUMPLE.** Las siete son `required`; payload incompleto, extra o inválido produce errores y no escribe. Los tests cubren cada campo inválido, cada omisión y campos extra. La actualización conserva `value_type`, `is_secret`, `module_code`, `description` y demás columnas; solo cambia `config_value`, `updated_by_user_id` y `updated_at`.
5. **Atomicidad de escritura y auditoría — CUMPLE.** `DB::transaction` envuelve la licencia, las escrituras y `AuditLogger::record`; el fallo de auditoría revierte todo. Se audita únicamente `changed_keys`, sin valores. Sin cambios no hay update ni evento. Tests de rollback y de no-op pasan.

La lectura expone `read_only` para deshabilitar la UI. No se creó política nueva.
7. **Cobertura de tests — CUMPLE.** Defaults, lectura sin escritura, persistencia/normalización, preservación de PII/secretos/comprobante/otras filas, inválidos/extra/incompletos, rollback de auditoría, no-op, licencias (sin gracia, gracia vencida, gracia futura, sin fila), autorización global/por sucursal/no autenticado, contrato de middleware, PATCH 405 y componente Inertia.
