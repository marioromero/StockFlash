### Mayores (no bloqueantes para este QA; corregir antes de cierre/difusion si ChatGPT lo estima)

- **M-01 - Password Admin en flash de sesion ante error de validacion (seguridad/privacidad).** `SetupRequest` usa `admin_password`/`admin_password_confirmation`; el manejador de Laravel hace `withInput(Arr::except($request->input(), $this->dontFlash))` y `dontFlash` solo excluye `current_password`, `password` y `password_confirmation` (`vendor/laravel/framework/.../Exceptions/Handler.php:190,897`). Ante un 422 (por ejemplo email duplicado o sucursal invalida) la contraseña en claro queda en el flash de la sesion; `config/session.php:21` define por defecto driver `database` (no se leyo `.env` real; driver efectivo no inspeccionado). Impacto: secreto transitoriamente en almacenamiento server-side. Recomendacion: declarar `protected $dontFlash = ['admin_password', 'admin_password_confirmation', ...]` en `SetupRequest`. No corregido por ser revision.
- **M-02 - Regresion del flujo DEV `admin:setup` (operabilidad).** `AdminSetupCommand` ejecuta `migrate` + `db:seed` (`SystemConfigsSeeder` deja `is_setup_completed='0'`) y crea el admin (`app/Console/Commands/AdminSetupCommand.php:28-30,44`). Con el nuevo guard, esa instalacion queda bloqueada: `/setup` muestra `INSTANCE_NOT_PRISTINE` y las rutas privadas redirigen a `/setup`; no hay test de este comando. El packet exige no eliminar el comando (se conserva), pero su resultado deja de ser usable. Recomendacion: marcar el flag en el comando DEV o documentar que el bootstrap DEV ahora es `/setup`. No se modifico codigo.
