## Scope and implementation
- Initial stock only (no adjustments, no catalog import). Reuses `StockWriteService::loadInitial` and the append-only `StockLedger` under one outer transaction.
- CSV format: UTF-8 (optional BOM), CRLF/LF; header `sku` + `quantity`/`cantidad`; delimiter `;` if present on the first line, else `,` (Chilean Excel supported); quoted fields supported.
- Technical limits: 512 KB file, 500 data rows, SKU/quantity field bounds; malformed encoding/header/quoting/blank rows/duplicates/unknown/ambiguous/ineligible/already-initialized SKUs fail closed.
- Quantities: strict positive DECIMAL(12,3), exact string validation, no floats, no truncation, no zero/negative/exponent/comma.
- Preview revalidates bytes and current DB state; commit re-parses the newly uploaded file (never trusts client preview), validates all rows, then runs ONE outer transaction for the whole batch. Variant items are processed in ascending variant order so ledger row locks are acquired deterministically; any failure rolls back every movement, `current_stock` change and audit.
- No direct `current_stock`/`stock_movements` writes in the import service; no `adjustment` type; no schema/table changes; no reserved changes.
- Branch only from authorized route using the same `is_numeric -> ID` resolver as middleware (`1E0` regression covered); actor from session; module/license/RBAC gates enforced on preview and commit; read-only license may view/template but cannot import.
- Template is generated in-memory as an attachment (UTF-8 BOM + `sku;cantidad`); uploaded files are read from Laravel's temporary non-public path and never stored/published/logged.
- Since the historical remote-DB exception, all bootstrap/Artisan/test activity for this work is run with explicit isolated SQLite `:memory:` configuration; no remote DB reads/writes were performed during resume.
- HQAEFF-001 guard respected: mandatory deterministic full gates only; no `--reuse-evidence`, no fabricated proof; independent read-only QA still required.
