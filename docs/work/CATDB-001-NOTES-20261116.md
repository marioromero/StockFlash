## Constraints, FK e índices implementados

- `tax_rates.code` UNIQUE; `categories.slug` UNIQUE; `brands.slug` UNIQUE; `tags.slug` UNIQUE; `attributes.name` UNIQUE.
- `attribute_values` UNIQUE `(attribute_id, value)`; FK `attribute_id` → `attributes` CASCADE.
- `products.internal_code` UNIQUE; `product_variants.sku` UNIQUE; `product_barcodes.barcode` UNIQUE.
- `categories.parent_id` → `categories` RESTRICT (self FK).
- `categories.default_tax_rate_id`, `products.tax_rate_id`, `product_variants.tax_rate_id` → `tax_rates` SET NULL.
- `products.category_id` → `categories` SET NULL + índice; `products.brand_id` → `brands` SET NULL + índice.
- `products.type` índice; `products.is_active` índice; `product_variants.is_active` índice.
- `product_variants.product_id` → `products` CASCADE; `product_barcodes.variant_id` → `product_variants` CASCADE.
- `product_tag` PK `(product_id, tag_id)` con FK CASCADE a `products` y `tags`; sin id ni timestamps.
- `product_variant_attribute_values` PK `(variant_id, attribute_value_id)` con FK CASCADE a `product_variants` y `attribute_values`; sin id ni timestamps.
- Soft delete (`deleted_at` nullable) solo en `categories`, `brands`, `products`, `product_variants`.
- Dinero `DECIMAL(14,2)`, costos `DECIMAL(14,4)`, porcentajes `DECIMAL(5,2)`, booleanos `TINYINT(1) UNSIGNED`, `sort_order` `SMALLINT UNSIGNED`.

## Verificado dinámicamente en SQLite `:memory:`

- 24 pruebas verdes en `tests/Feature/Catalog` (552 assertions): esquema, constraints, seguridad del lote CORE y reversibilidad.
- Guard de seguridad en los 3 tests: driver `sqlite` y base `:memory:` comprobados antes del DDL.
- Existen exactamente las 11 tablas de catálogo, con columnas exactas y sin columnas inventadas; defaults y timestamps/SD comprobados.
- Índices únicos, índices no únicos y PK compuestas comprobados vía `Schema::getIndexes`.
- Inserción válida de extremo a extremo y errores reales UNIQUE en las 9 claves únicas.
- FK inválida (`categories.parent_id`, `product_variants.product_id`) produce `QueryException`.
- RESTRICT, CASCADE y SET NULL comprobados con borrados reales en SQLite.
- Soft delete: la fila persiste y el UNIQUE no se libera.
- Reversibilidad: `down()`/`up()` del archivo de migración cargado dentro de la transacción de prueba; las 11 tablas desaparecen y reaparecen sin afectar las tablas CORE clave.
- Las 20 migraciones CORE `2026_10_16_000001..000020` siguen presentes con el mismo listado de archivos y no crean tablas de catálogo.

## Verificado solo estáticamente

- Precisiones DECIMAL exactas (`14,2`, `14,4`, `5,2`) y longitudes VARCHAR, por inspección del archivo de migración.
- Miembros literales de los ENUM: `products.type`, `products.origin`, `product_variants.unit`, `product_barcodes.type`.
- `FULLTEXT` de `products.name`: declarado condicionalmente para los drivers `mysql` y `mariadb` (`in_array(DB::connection()->getDriverName(), ['mysql', 'mariadb'], true)`). En SQLite no se crea ni se simula; no se verificó el índice FULLTEXT real.
- Comportamiento real de ENUM, FULLTEXT, EXPLAIN y del motor InnoDB/MariaDB no ejecutado.
