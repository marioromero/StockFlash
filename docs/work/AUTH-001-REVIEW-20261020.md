## 2. Modelo User — campos reales DB-001 (§4.9)

`app/Models/User.php` declara en `$fillable`/`$casts`: email, password, global_role_id, default_branch_id, pin_hash, pin_failed_attempts, pin_locked_until, mfa_enabled, mfa_secret_encrypted, mfa_confirmed_at, max_discount_percent, max_return_amount, is_active, failed_login_attempts, locked_until, must_change_password, last_login_at, last_login_ip, password_changed_at (en casts). Relaciones: globalRole, defaultBranch, branchAssignments, branch_users. Métodos: isGlobal, isActiveAccount, isLocked, mustChangePassword, incrementFailedLogin, clearFailedLogin, recordLogin. `$hidden` oculta password/remember_token/pin_hash/mfa_secret_encrypted.

**Observación 1:** `password_changed_at` no figura en `$fillable` (sí en `$casts`). `PasswordController` usa `forceFill`, por lo que funciona en runtime. No bloquea; corregir para consistencia.

## 3. Login / Logout

- `LoginController@store`: valida email+password, rate limiting 5 fallos vía `RateLimiter`, `Auth::attempt`, `session()->regenerate()`, registra `last_login_at`/`last_login_ip` (`recordLogin`), redirige a `/dashboard`; si `must_change_password` redirige a `/password/change`.
- Cuenta inactiva (`is_active=0`) y `locked_until` futuro impiden el ingreso (403/mensaje, sesión invalidada si se autenticó por error).
- `LogoutController@destroy`: `Auth::guard('web')->logout()`, `session()->invalidate()`, `session()->regenerateToken()`, redirige a `/login`.

## 4. Cambio de contraseña

- `PasswordController@update`: `current_password` obligatorio, `password` con `min:15` (desde `config('system_configs.password_min_length', 15)`), `confirmed`, rechaza igual a la actual, lista de contraseñas comunes bloqueadas, actualiza `password` + `password_changed_at` + `must_change_password=false`, invalida sesión y redirige a `/login`.
- `PasswordChange.vue`: hint "Mínimo 15 caracteres", tres campos, autocompletado adecuado.

**Observación 4:** HTML/docs indican "máximo 64 caracteres", pero el controlador no aplica `max`. SEC-01 exige "máximo ≥64"; no incumple. Bcrypt trunca a 72 bytes.

## 5. Comando admin:create (DEV local/testing)

- Firma `admin:create {--email=}`. Entorno restringido a `local`/`testing` (`isLocalEnvironment`).
- Correo vía opción `--email` o `ask()` interactivo. Contraseña **únicamente** vía `$this->secret()` (entrada oculta, nunca argumento visible en línea de comandos).
- Valida mínimo 15 caracteres, unicidad de correo, existencia del rol `central_admin`, crea con `global_role_id = central_admin->id`, `is_active = 1`, `must_change_password = false`.
- No deja credenciales predefinidas, no marca onboarding, no crea sucursales, no escribe secretos en logs/repositorio.

## 6. RBAC server-side (tablas DB-001)

- `CheckPermission`: para `global_role_id` no nulo consulta `roles→role_permissions→permissions`; para usuario por sucursal consulta `branch_user→role_permissions→permissions` con `branch_id` de ruta/request/default. Sin asignación → 403. Sin permisos directos a usuarios.
- `EnsureBranchAccess`: global accede a todas; por sucursal solo si tiene fila en `branch_user`; resolución por código o ID; sin asignación → 403.
- Verificación en cada request protegido, independiente de la UI.

## 7. VerifySession — SEC-05

- Rechaza `is_active = 0` (logout + invalidate + 403).
- Duración absoluta: `last_login_at + session_absolute_hours` (12 h) → 403 si excedido.
- Inactividad: `last_activity` de sesión + `session_idle_minutes_pos` (30) / `session_idle_minutes_admin` (60) según `isGlobal()` → 403 si excedido.
- Actualiza `last_activity` en cada request protegido.
- Valores leídos de `system_configs` con por defecto (12 / 30 / 60).

## 8. Pruebas ejecutadas (26 passed / 65 assertions)

Ejecución real vía `php artisan test tests/Feature/Auth` (Registro AUTH-001-VERIFY, gate a10, exit=0):

- LoginTest (5): login exitoso → dashboard, contraseña incorrecta → guest, 5 fallos → bloqueo + `locked_until`, no autenticado → `/login`, **logout → invalida sesión + redirect `/login`**.
- PasswordTest (5): cambio exitoso + `password_changed_at`, actual incorrecta, nueva muy corta (<15), no autenticado → `/login`, cambia e inicia sesión con nueva.
- RbacTest (9): cajero sin `users.manage` → 403, admin global con permiso → 200, sucursal A no accede B → 403, sucursal A accede A → 200, admin global sin sucursal → dashboard 200, revocación de permiso → 403, cuenta desactivada → no autentica, cambio de rol → permisos reevaluados, usuario sin sucursal → ruta con sucursal 403.
- SessionTest (7): desactivado en request posterior → 403/guest, expira absoluta (>12h) → 403, no expira antes (11h) → 200, expira inactividad POS (>30m) → 403, no expira antes POS (29m) → 200, expira inactividad admin (>60m) → 403, no expira antes admin (59m) → 200.

**Todas las pruebas de RBAC y sesión hacen peticiones HTTP reales** (`actingAs` + `get`/`post`, aserciones 403/200). Las de sesión manipulan `last_activity` (`->session(['last_activity' => ...])`) y `last_login_at` (`now()->subHours(13/11)`).
