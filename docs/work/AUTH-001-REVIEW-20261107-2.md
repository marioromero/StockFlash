## Defecto 2 - Bypass de sucursal para usuario global

**Estado: corregido.**

- Se elimino el early-return que devolvia `$next($request)` para `isGlobal()` antes de resolver la sucursal.
- Orden de resolucion vigente: ruta `branch` -> parametro del middleware con firma `?string $branchId` -> `branch_id` del request -> `default_branch_id` del usuario.
- Sin identificador (`null` o cadena vacia): `403`.
- La sucursal se busca por ID si el identificador es numerico, o por `code` si no lo es.
- Si la sucursal no existe o esta soft-deleted, se responde `403` antes de cualquier retorno global. Esto aplica tambien al usuario global.
- Con sucursal valida:
  - usuario global: `$next($request)`;
  - usuario no global: ademas se exige fila en `branch_user` para esa sucursal; si no, `403`.
- No queda ninguna referencia a `route('brand')` ni al parametro de ruta `brand` en `app/` o `routes/`.
- Pruebas que cubren el contrato:
  - global + codigo inexistente -> 403;
  - global + ID inexistente -> 403;
  - global sin contexto de sucursal -> 403;
  - global + sucursal valida -> 200;
  - no global + sucursal propia -> 200;
  - no global + sucursal ajena -> 403;
  - parametro de middleware por codigo (`branch.access:SUC-A`) -> 200;
  - sucursal soft-deleted para usuario no global -> 403.
